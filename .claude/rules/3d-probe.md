# 3D 씬 · 모션 · 프로브 — 되돌리면 다시 데는 것

room-3d·프로브 스크립트를 만질 때만 로드된다(경로 조건부, 2026-09-17 분리).
전부 실측으로 얻은 것이고 **화면상 구별이 안 되는 실패**들이다.

## 🔴 자동 수정이 앱을 죽인 적이 있다 — 고친 뒤 반드시 띄워본다

`biome check --write` 가 NestJS 주입 대상의 import 를 `import type` 으로 바꿔
**api 가 기동조차 못 했다.** 그런데 `pnpm build` 는 초록이었다(2026-09-09 실측).

→ `apps/api` 는 Biome 대상에서 뺐다(근거: `apps/api/왜-biome-을-안-쓰나.md`).
→ **api·web 을 고친 뒤에는 실제로 띄워서 확인한다.** 빌드 통과는 증거가 아니다.

⚠️ `grep "^import type" apps/api/src/` 를 게이트로 쓰지 않는다. **`import type`
자체는 문제가 아니다** — DI 대상(생성자 주입)과 `ValidationPipe` 가 보는 DTO 에만
해로우며, 순수 타입 참조에는 정당하다(실측: `contact.service.ts` 가 그 경우인데
게이트가 위반으로 잡아 잘못된 결론을 냈다). 판정은 **띄워서 `/…/status` 가
응답하는가**로 한다.

```bash
pnpm verify                      # lint · typecheck · test · 방 검사 · 데이터 검사
pnpm --filter @neighbor/api build && API_PORT=21201 node apps/api/dist/main.js &
curl -s http://localhost:21201/diagnose/status
pnpm --filter @neighbor/web build && PORT=21200 pnpm --filter @neighbor/web start &
node scripts/verify-rendered.mjs # 렌더된 화면을 공개 검사기로
```

## 🔴 화면은 눈으로 본다 — 검사기만으로는 못 잡는 것이 있다

실측 2026-09-09, **데이터 검사를 통과한 상태에서** 화면에 나가 있던 것들:

- `@hyunwoo/ui` — 개인 스코프 패키지명이 스택 태그에 실렸다
- `카페24` — 플랫폼 실명이 경력 요약 라벨에 실렸다
- 책장에 170종이 깔려 아무것도 안 읽혔다(정본의 stack 이 기술명이 아니라 서술이다)

셋 다 **스크린샷을 열어보고서야** 발견했다. 그 뒤 검사 항목으로 추가했지만,
검사기를 늘리는 것과 별개로 화면은 계속 눈으로 본다.

## 🔴 3D 프로브는 headless 로 열되 **GPU 플래그를 준다** (2026-09-16 갱신)

아래 "headless 로 재지 않는다" 는 **기본 옵션 기준**이었다. 진짜 원인은 창이
아니라 **렌더러**다 — 기본 headless 는 SwiftShader(소프트웨어)로 떨어진다.

```
headless 기본            11fps   ANGLE (SwiftShader)
headless + angle=metal   61fps   ANGLE (Apple M3 GPU)
```

`scripts/probes/_pw.cjs` 의 `LAUNCH` 를 쓴다(`chromium.launch(LAUNCH)`).
**`headless: false` 를 쓰지 마라** — 진짜 창이 뜨고, `canvas-probe` 는 마커마다
컨텍스트를 열어 창이 연달아 튀어나온다. `--window-position` 으로 화면 밖에
보내려 해도 macOS 는 그 좌표를 무시한다(실측).

## 🔴 3D 모션은 headless 로 재지 않는다 — 없는 증상이 만들어진다

실측 2026-09-10. headless 크로뮴은 GPU 가 없어 **12fps** 로 떨어진다.
그 상태로 모션을 재면 **멀쩡한 것이 고장으로 보인다**:

| 증상 | headless | headed(실제) |
|---|---|---|
| 마커 등장 | 3.5초에 걸쳐 2→3→6→7 | **67ms 안에 0→7** |
| 입장 연출 | 0.9초에 이미 최종 구도(=안 돈다) | **정상으로 돈다** |

이 둘을 버그로 잡고 고치려다 되돌렸다(이슈 #14). 프로브는
`chromium.launch({ headless: false })` 로 연다.

## 🔴 모션은 매 프레임으로 재고, 마지막 판정은 눈으로 한다

**정지 스크린샷 몇 장과 200ms 샘플링으로 "정상" 이라 판정해 왔는데 전부 틀렸다.**
사용자가 화면을 보고 지적했고, 매 프레임(`requestAnimationFrame`) 기록으로
다시 재니 문제 4건이 나왔다(#8·#9·#10·#15·#17).

그리고 **자동 지표가 아예 없는 문제가 있다.** 현관문이 화면을 검게 만든 건(#17):

- "화면 안 마커 수" → 클램프 때문에 **늘 7/7** 로 정상이라고 나온다
- 캔버스 밝기 → 2D 컨텍스트로 읽으면 **전부 0** 이 나온다

`.wip/verify-each-object.cjs` 는 그래서 촬영만 하고 판정은 사람이 한다.

### ⚠️ 2026-09-17 정정 — 캔버스는 **읽을 수 있다. 순서 문제였다**

위 "WebGL 이라 못 읽는다" 는 **틀렸다.** drawingBuffer 는 합성 뒤 비워지므로,
**R3F 의 렌더 콜백보다 *뒤에* 도는 rAF** 안에서 읽으면 그대로 나온다.

```
앞에서 읽음   mean 0     max 0      ← 여태 밟던 것
뒤에서 읽음   mean 20.4  max 255
```

⚠️ **문서 시작에 rAF 를 걸면 영영 R3F 앞이다** — 각자 콜백 안에서 재등록하므로
   최초 순서가 고정된다. 0 이 연속 읽히면 `setTimeout` 을 한 번 거쳐 줄 맨
   뒤로 다시 선다.

→ 이 방법이면 **마커(DOM 프록시)가 없는 하위 화면도 매 프레임 구도를 잰다.**
  스크린샷을 찍어 페이지 안 2D 캔버스에 다시 그리는 방식
  (`verify-page-3d`·`verify-intro-state`)보다 훨씬 촘촘하다.

⚠️ 그리고 **평균 휘도로 구도를 판정하지 마라.** 구도가 완전히 달라도 평균이
   우연히 비슷하다 — 실측 2026-09-17: 잘못된 구도 21.8 vs 제 구도 19.4(배율
   1.12)라 **되돌리기 검증이 안 잡혔다.** 같은 자리의 **픽셀을 직접 비교**한다
   (`verify-intro-state` 의 `DIFF`).

**그래도 마지막 판정은 눈으로 한다.** 수치가 통과해도 화면이 이상할 수 있다.

## 🔴 "이름만 있고 정의 없는 것" 은 아무도 안 잡는다 (2026-09-16)

`RoomPanel` 이 `animate-[panelIn_.44s_...]` 를 쓰는데 **`panelIn` 키프레임이
어디에도 없었다.** 브라우저는 모르는 이름을 조용히 무시하므로 패널이 한 프레임에
0 → 100 으로 튀어나왔다 — `getAnimations()` 가 빈 배열이었다.

**빌드·타입체크·lint·브라우저 프로브가 전부 통과했다.** 사용자가 "확 나타난다" 고
지적하고 나서야 찾았다.

→ `node scripts/verify-animations.mjs` 가 쓰는 이름과 정의된 키프레임을 대조한다
  (`pnpm verify` 에 포함). 되돌리기 검증 완료 — 키프레임 이름을 바꾸면 잡는다.

⚠️ 같은 형태가 CSS 변수·`data-*` 속성·Tailwind 임의값 어디서든 난다.
   **"설정했다" 와 "그게 실제로 쓰인다" 는 다르다.**

## 🔴 라이브러리가 매 프레임 되돌리는 값을 연출로 덮어쓰지 않는다 (2026-09-16)

입장 연출이 카메라를 `[-4.7, 1.35, -1.6]`(문 밖)에 놓는데, `OrbitControls` 의
`CAMERA_LIMITS`(`minDistance 4.6`, 방위각 `PI*0.54~0.98`)가 `update()` 마다
카메라를 제약 안으로 끌어당겼다.

- 시작 위치가 실제로는 `[3.53, 1.73, -0.77]`(**이미 방 안**)이었다 —
  "문 밖에서 들어온다" 가 **한 번도 실현된 적이 없었다**
- 비행 중간(진행 0.45)에 제약 경계를 넘으면서 **한 프레임에 좌우각이 79.3°** 꺾였다
  → 사용자가 "갑자기 화면이 휙 돈다" 고 한 자리

→ 연출이 좌표를 직접 넣는 구간에서는 **제약을 풀고, 끝나면 되돌린다**(`FREE_LIMITS`).

## 🔴 전환은 "순차" 가 아니라 "겹침" 이다 (2026-09-16)

나가는 연출 → 라우트 교체 → 들어오는 연출로 붙이면 **두 화면이 겹치는 순간이
한 프레임도 없다.** 곡선·타이밍을 아무리 다듬어도 "끊고 다시 시작" 으로 보인다.
프레임률은 60fps 로 멀쩡했으니 성능이 아니라 **구조** 문제였다.

→ **View Transitions API** 가 그 겹침을 해 준다. 브라우저가 이전 화면을 스냅샷으로
  잡아 GPU 에서 합성한다.

⚠️ `React.unstable_ViewTransition` 이 없고 Next 플래그도 없다고 **"못 쓴다" 로
   결론내지 마라.** 그건 프레임워크 통합이 없다는 뜻이고 네이티브 API 는 그대로 있다
   (이 저장소가 한 번 그렇게 포기했다).

⚠️ VT 와 **진입 애니메이션을 같이 쓰면 안 된다.** `initial: opacity 0` 인 요소가
   있으면 VT 가 새 화면을 찍는 순간(58ms) 그 화면이 투명해서 **겹칠 그림이 없다.**
   화면을 잇는 일은 하나가 맡는다.

## 🔴 3D 씬은 캔버스와 같은 층에 둔다 (2026-09-16)

캔버스를 `layout` 에 올려 두고 **씬을 페이지 안에 두면** 라우트가 바뀔 때마다
씬이 죽고 다시 산다 — GLTF 21개를 다시 세팅하느라 **전환마다 91ms 멈춤**이 났다
(3회 전부 재현).

→ R3F 표준 배치: **Canvas 도 Scene 도 root 에 하나.** 화면은 `RoomStage` 로
  "지금 무엇을 보는가" 만 선언한다.

| | 씬이 페이지 안 | 씬을 캔버스에 고정 |
|---|---|---|
| 중앙값 | 20~21ms | 16.7ms |
| 100ms 초과 | 2개 | **0개** |

## 🔴 등장 연출이 **서버가 그린 글을 감추면** 안 된다 (2026-09-17)

`template.tsx` 가 Motion 으로 페이지를 페이드하고 있었다. 그 결과 서버 HTML 의
**`<body>` 첫 요소가 `<div style="opacity:0">`** 이 됐다 — 하이드레이션 전에는
화면에 아무것도 없다.

```
실측(프로드 빌드, /work): 제목 첫 등장 363ms · 완전표시 676ms
고친 뒤:                  완전표시 204ms
```

이 사이트는 **검색 유입이 곧 수주 경로**인데 LCP 요소를 JS 뒤로 미루고 있었다.
JS 를 **끈** 사람은 `layout.tsx` 의 noscript 가 구해 주지만, JS 가 **느리거나
실패한** 사람은 아무도 안 구해 준다.

같은 형태가 `SplitText` 에도 있었다 — 서버가 그린 제목을 낱글자로 갈아끼우며
`opacity: 0` 에서 출발시켜 **이미 읽히던 글자를 도로 감췄다.**

→ 등장 연출은 **"감췄다 보이기" 가 아니라 "보인 채로 움직이기"** 로 만든다.
  낱글자는 `y` 와 `blur` 만 움직이고 `opacity` 를 건드리지 않는다.
→ 화면 **전환**의 겹침은 View Transitions 하나가 맡는다. 그 위에 페이드를 또
  얹으면 두 겹으로 곱해진다(`tokens.css` 의 `::view-transition-*`).
→ `scripts/probes/verify-title.cjs` 가 "보였다가 다시 감춰지는가" 를 본다.

⚠️ `Reveal`(스크롤 등장)의 `opacity:0` 은 남는다 — 역할이 다르고 noscript 가 덮는다.

## 🔴 뷰포트 기준 값을 **캔버스 픽셀**에 쓰지 않는다 (2026-09-17)

`setViewOffset` 보정량을 본문 폭(980px)으로 계산해 캔버스에 걸고 있었다.
하위 화면의 캔버스는 `--cv-left` 로 오른쪽 띠에 들어가 **340px** 인데 **490px** 을
밀었다 — 물건이 화면 밖으로 나가 **사실상 검은 화면**이었다.

```
실측(/work): 평균휘도 11 · 최대 20   (홈은 최대 255)
고친 뒤:     평균휘도 26 · 최대 250
```

**홈에서는 우연히 맞는다** — 거기서는 캔버스가 뷰포트를 다 쓰므로 "왼쪽 UI 520px"
이 곧 "캔버스를 덮는 520px" 이다. 하위 화면에서만 갈렸다.

→ 덮는 폭은 **캔버스 픽셀로** 잰다. 하위 화면에서 캔버스를 덮는 것은 본문이 아니라
  **왼쪽 마스크(42%)** 뿐이다.
→ `verify-page-3d.cjs` 가 하위 화면의 3D 휘도를, `verify-resize.cjs` 가
  세로 리사이즈 복귀를, `verify-canvas-fit.cjs` 가 `--nav-h`·`--foot-h` 추종을 본다.

## 🔴 프로브 판정이 **위양성**을 내는 세 가지 (2026-09-17, 한 세션에 셋 다 밟았다)

새 검사기를 만들 때마다 처음 판정이 틀렸고, 그 상태로 **"무력화해도 안 잡힌다"**
는 잘못된 결론을 냈다.

| 밟은 것 | 증상 | 고친 방법 |
|---|---|---|
| 낱글자 대신 **단어 래퍼**를 셌다 | 불투명도가 늘 1 | 잎 노드(`childElementCount === 0`)만 |
| 조상의 `clip-path`·1px 을 안 봤다 | 접힌 링크를 "보인다" 로 셈 | 조상을 거슬러 올라가며 검사 |
| **이동 완료를 안 기다렸다** | 홈을 잰 채 하위 화면이 통과 | `waitForURL` + `data-canvas-mode` 대기 |

그리고 **0 은 "없다" 가 아니라 "못 읽었다" 일 수 있다.** 교차 출처 스타일시트의
`cssRules` 가 던지는 것을 `catch` 가 삼켜 "웹폰트가 로드되지 않는다" 는 **틀린
이슈**를 팠다(#41 — 실제로는 343KB · 44파일이 멀쩡히 적용 중이었다).

→ 새 검사기는 **반드시 무력화해서 빨개지는지** 본다. 그리고 **"안 잡혔다" 와
  "안 바뀌었다" 를 가른다** — 치환 스크립트에 `count == 1` 단언을 걸고, 바뀐 것을
  `grep` 으로 눈으로 확인한 뒤 돌린다.
→ 복구는 **파일 복사**로 한다. `git checkout <파일>` 은 같은 파일의 다른 수정까지 날린다.

## 🔴 카메라 제약은 "언제" 가 아니라 **"그 순간 카메라를 담는가"** 로 고른다 (2026-09-17)

**한 자리에서 네 번 틀렸다.** 리뷰 3·4·5차가 연달아 같은 곳에서 회귀를 잡았다.

| 무엇을 했나 | 무엇이 깨졌나 |
|---|---|
| 제약을 비행 **시작**에 걸었다 | **들어가는** 비행이 첫 프레임에 30.6% 당겨짐 (202px) |
| 비행 **끝**에만 걸었다 | **나오는** 비행이 상한에 잘려 구도가 **영구히** 안 돌아옴 (205px) |
| `abort` 에서도 걸었다 | 비행이 없는 pointerdown 에도 돌아 **FOCUS 제약이 통째로 죽음** (자유도 31% 손실) |
| `abort` 에서 **목적지** 제약을 걸었다 | 중단 시 한 프레임에 **30%·97°** 튐 |

마지막 것은 **바로 앞 회전이 지운 주석이 정확히 경고하던 경우**였다.

**규칙:**

1. **거는 시점이 아니라 담는 범위로 고른다.** 어느 시점이든 거는 범위가
   **그 순간 카메라 자세를 담지 못하면** `OrbitControls.update()` 가
   **한 프레임에 잘라낸다.** 그게 "갑자기 화면이 휙 돈다" 의 정체다.
2. **경로 전체를 담는 것은 출발도 도착도 아닌 합집합이다**(`FLIGHT_LIMITS`).
   출발 것을 끝까지 두면 도착이 잘리고, 도착 것을 시작에 걸면 출발이 잘린다.
3. **중단 지점에서는 아무것도 걸지 않는 것이 가장 안전하다** — 이미 걸려 있는
   합집합이 그 자세를 담고 있다. 다음 비행이 착지하며 정확한 것을 건다.
4. ⚠️ **합집합을 입장 비행에 걸지 마라.** 입장 시작 방위각이 237.3° 인데
   합집합 상한이 194.4° 다. 입장은 `Scene` 이 `FREE_LIMITS` 로 연다.
5. 🔴 **주석을 지울 때는 그 주석이 막고 있던 것부터 본다.**

⑦(비행 **도중** 드래그, 대조군 차이).
