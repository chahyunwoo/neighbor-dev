# apps/api 의존성 선택 근거

> 최신 버전을 안 쓴 자리는 이유를 남긴다. 근거가 없으면 다음 세션이
> "왜 낡은 걸 쓰지?" 하고 올렸다가 같은 문제를 다시 밟는다.

## NestJS 는 11 라인이다 (12 아님) — 2026-09-09 실측

`@nestjs/throttler` 가 **NestJS 12 를 지원하는 버전을 아직 내지 않았다.**

```bash
pnpm view @nestjs/throttler versions   # → 6.5.0 이 최신, 7.x 없음
pnpm view @nestjs/throttler@6.5.0 peerDependencies
# → @nestjs/common: '^7.0.0 || ^8.0.0 || ^9.0.0 || ^10.0.0 || ^11.0.0'
```

NestJS 12 로 올리면 이 peer 가 깨진다. throttler 는 **AI 자가진단의 rate limit**
이고 기획서 5절이 "일일 총량 캡이 비용 방어의 본체"라고 못박은 부분이라,
peer 경고를 무시하고 도박할 자리가 아니다.

→ throttler 가 NestJS 12 를 지원하면 그때 함께 올린다. 위 명령으로 확인한다.

## @nestjs/config 만 12.x 다

버전 체계가 본체와 다르다. 12.0.0 이 NestJS 11 을 정식 지원한다.

```bash
pnpm view @nestjs/config@12.0.0 peerDependencies
# → { rxjs: '^7.1.0', '@nestjs/common': '^11.0.0 || ^12.0.0' }
```

4.0.4(직전 버전)는 `^10.0.0 || ^11.0.0` 이라 이것도 쓸 수 있으나,
12.0.0 이 NestJS 12 로 올릴 때까지 그대로 간다.
